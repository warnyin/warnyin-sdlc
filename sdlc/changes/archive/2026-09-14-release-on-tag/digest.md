# Digest — release-on-tag (deep, shipped 2026-09-14)
- Shipped: pushing a plain `vX.Y.Z` tag publishes via `.github/workflows/release.yml`. It runs `ci.yml` as its gate (`workflow_call`), then `release-check.mjs` (tag == package.json, npm ≥ 11.5.1), then checks the tag is on main, then `npm publish --provenance --access public` over OIDC with no token. Actions are SHA-pinned in the job that holds `id-token: write`. README gains a "Releasing" section and CLAUDE.md the rules for ci.yml as a called workflow.
- Specs merged: new `release-pipeline` (3 requirements, 5 scenarios). `## Purpose` was an empty placeholder after archive and was filled inside the ship gate.
- Assumptions: OIDC over `NPM_TOKEN` and notice-only were human choices. Tag push, not GitHub Release. Pre-release tags publish nothing. Every release becomes `latest`, since there are no maintenance branches.
- Contract: attacked twice. Round 1 added `continue-on-error`/`always()`, tag case/space/leading zeros, the npm check moved into the script (stdin) and `persist-credentials: false`. Round 2 (after review widened the delta) caught `|| true` evading substring-matched gates, so gate `run:` values are now asserted exactly.
- Verify: 1 round, `mode=panel`: `npm test` 276/276, evaluator 5 on every line. Its trajectory scores rest on the task log the main loop supplied. After the review fixes: 279/279, 20 contract rows, and 10 workflow mutations each turned a test red.
- Review (`mode=panel`, 4 reviewers): 0 real blockers. Ops and quality both claimed the tag filter treats `+` literally; GitHub's docs source says `+` = one or more of the preceding character, so it was refuted. Applied improvements: SHA pinning, tag-on-main ancestry check (added to Delta), pack-verify on Node 24, `\bsecrets\b`, escape-hatch checks over ci.yml, no concurrency group, and tag/version compared before the npm check.
